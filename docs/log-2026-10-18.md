## Правила, которые держим
- Название номера копируется как продаёт отель. Ничего не придумываем: ни вид, ни расстояние, ни звёзды, ни цену. Цен на сайте нет.
- Если ярлык на сайте бронирования («City view») спорит с названием номера, верно название, и страница так и пишет.
- Отель без категории с видом, но с отчётами гидов, получает уровень `reported`, не `listed`.
- Только свободные лицензии у фото, автор подписан. Ночных фото Эйфелевой башни нет.
- Билеты и транспорт: только товар, который мы видели на странице продавца, название как у продавца, в заметке только то, что сказано там.
- Никаких статей «лучший eSIM для Турции» и «билеты в Колизей»: там выигрывают гиганты, и тема сайта размывается.

## Каркас и дизайн: что где лежит и что дорого
Сайт собран из трёх слоёв, и они почти не зависят друг от друга.

| Слой | Где | Размер |
|---|---|---|
| Данные: виды, отели, номера, источники | `src/data/views/*.json` | около 2600 строк, 11 файлов |
| Шаблоны: как данные превращаются в страницы | `src/pages`, `src/components`, `src/layouts` | 25 файлов, около 2000 строк |
| Оформление: цвета, шрифты, отступы | `src/styles/global.css` и стили в компонентах | около 250 строк в общем файле |
| Автоматика: фото, ссылки, кандидаты, проверки, выкладка | `scripts/`, `.github/workflows/` | 10 скриптов, 2 процесса |

- Смена цветов, шрифтов, отступов: правка значений в `global.css`, меняются все 42 страницы.
- Смена вида страницы (карточки отелей, верх страницы, главная): правка нескольких компонентов, все виды обновляются сами. Данные не трогаем.
- Совсем новый дизайн: переписываем слой шаблонов и оформления. Данные, переходы `/go/`, фото, выкладка, проверки и партнёрские ссылки остаются. Проверка `npm run check:site` ловит поломку (alt у картинок, ссылки, один h1).
- Правила дизайна лежат в `CLAUDE.md` (названия номеров в стиле `.room`, арочные рамки, пары «≠», кнопки от 44px, без прокрутки вбок): при редизайне их можно пересмотреть, но по умолчанию они сохраняются.
- Что стоило больше всего сегодня: не каркас, а исследование. Чтобы записать один отель, нужно найти страницу продавца и скопировать точные названия номеров. 56 отелей и 161 категория, это основная работа. Каркас строится один раз.
- Каркас готов: страницы видов, стран и городов, переходы, фото, проверка, выкладка, партнёрские ссылки. Не готово: автор видов (главная автоматизация), поле поиска, «Как добраться», статистика посещений, соцсети, подписка.
- Ограничение автора видов: часть сайтов отелей закрыта для программ-читателей. Тогда у вида будет меньше отелей (у Саграды Фамилии их 3) или уровень `reported`. Последнее слово остаётся за вами («ок» перед публикацией).

## Заметки для будущих сессий (ограничения среды)
- Из чата недоступны Wikimedia и Wikidata: фото и список кандидатов собирает только GitHub.
- Логи GitHub из чата не скачать (403). Скрипты печатают `::warning::`, их возвращает API аннотаций (`gh api repos/alexbogota/hotelsviewer/check-runs/<id задачи>/annotations`). Запуск процесса вручную: `gh api -X POST repos/alexbogota/hotelsviewer/actions/workflows/<файл>/dispatches -f ref=main`.
- Список секретов GitHub из чата тоже не прочитать (403).
- Сайт hotelsviewer.com из терминала чата недоступен (curl не проходит). Живую страницу смотреть через WebFetch (добавлять `?check=1`, иначе вернётся кэш), переходы `/go/` так проверить нельзя.
- `pkill -f` внутри команды убивает собственную оболочку. Процесс останавливать по номеру (PID).
- Локально проверка: `npm run build && npm run check:site`, тесты `npm run test:candidates` и `npm run test:partner-links`.
